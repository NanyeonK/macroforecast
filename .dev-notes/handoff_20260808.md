## Package defects found (Purpose 2)

### `MF-001` / #513 — k-fold CV was unseeded → fix in PR #515

`random_kfold_split` seeds itself with `random_state=0`. `make_splitter` declared
`random_state: int | None = None` and forwarded it **explicitly**, overriding the
callee's default. Every `validation_splitter("random_kfold", ...)` goes through
`make_splitter`, so every k-fold shuffle in the package drew from OS entropy.

Not last-bit noise. Five identical `select_params` calls:

```
best_score : 1.00970  0.98571  1.00746  0.97873  1.00451
AR order   : n_lag = 3, 4, 6, 3, 1          <- a different model each time
```

Two hypotheses died on measurement, and both looked right:

- *"a parallel artifact"* — no: `n_jobs=1` is non-deterministic too, 5× smaller.
- *"BLAS non-associativity"* — no: `AR,BIC` is bit-identical to ten decimals across
  all four runs, serial and parallel, and BIC selection issues the same `lstsq` calls.

Fix: four sites defaulted `None` and forwarded it; all now `0`, matching
`mf.window.random_kfold()`, which already promised a seed. This resolved an
inconsistency rather than setting a policy.

### `MF-002` / #516 — stochastic search is unseeded → **not fixed, needs your call**

Same shape, different surface: `SearchSpec.random_state` defaults to `None` and is
passed to the `random`/`genetic`/`bayesian` paths. With a *deterministic* splitter,
five identical random-search calls chose `alpha` 9.09 / 5.34 / 2.34 / 1.52 / 2.29.

Unlike #513, the defaults here all **agree** (`SearchSpec` and four builders are all
`None`), so changing it is a policy change across public entry points, not a
contradiction being resolved. Filed rather than fixed for that reason.
